# Передача RTL8153B / Wii U для Claude

Эти файлы написаны по текущим исходникам и сохранённым результатам 2026-11-09.
Они являются точкой входа, а не новым разрешением на установку или заменой проверки
текущих файлов. Разработка Codex остановлена по запросу паузы. Для этой передачи
выполнены чтение файлов и запись документации; сборки и аппаратные операции не запускались.

## Порядок чтения

1. ../../CLAUDE.md — ограничения владельца и границы первого задания.
2. CURRENT_STATE.md — что действительно готово, где последний непроверенный код.
3. ARCHITECTURE.md — карта реализации, ABI, владение памятью, loader.
4. BUILD_AND_TEST.md — среда, точные команды, ограничения доказательств.
5. EVIDENCE.md — результаты консоли, хеши, известные ошибки прошлых выводов.
6. NEXT_WORK.md — следующие задачи, критерии готовности, разделение работы.
7. CONSOLE.md — IP, FTP, TCP, SD, восстановление и условия аппаратных действий.
8. CLAUDE_PROMPT.md — готовый первоначальный запрос для Claude.

Затем прочитать существующие docs/NATIVE_COMPLETION_ABI.md,
docs/NATIVE_LOADER_DESIGN.md, docs/MOCHA_RELOAD_DIAGNOSTIC_AUDIT.md,
docs/MOCHA_BOOTSTRAP_INVESTIGATION.md, docs/NATIVE_INTEGRATION.md,
docs/DEBUGGING.md и соответствующие исходники/tests.

## Что передавать

Предпочтительный вариант — Claude Code на этом же ПК с доступом к проекту и WSL.
Ему нужны native/, driver/, aroma_module/, net/, scripts/, tests/, tools/, vendor/,
upstream/, docs/ и исходные Makefile/лицензии. Не ограничиваться build/ бинарниками.
Внешнему чату без файлов и выполнения тестов доступны лишь обзор/ревью, не верификация.

evidence/ и build/ игнорируются .gitignore, но локально важны: ARM-тесты читают
приватный owner ELF, а Boot State profile генерируется из локальных сборок.
Не загружать весь evidence в облако ради передачи контекста. При отсутствии файлов
Claude должен отметить недоступность нужного доказательства, а не создавать его заново
из догадок. Не скачивать чужую firmware вместо закреплённого owner image.

snapshot.json содержит контрольные суммы ключевых исходников/артефактов на момент
передачи. Это идентификатор снимка, не сертификат проверки и не список разрешённых
для установки файлов. Перед редактированием сравнить с текущим состоянием.

## Как читать старую документацию

docs/PPC_RECOVERY_0.1.1.md (бывший корневой README) исторически описывает PPC recovery 0.1.1 и содержит устаревшие
ограничения/статусы. Некоторые loader-документы содержат последовательные исторические
этапы «ещё не загружено»/«reload не выполнен». Более поздний аппаратный результат
в EVIDENCE.md и MOCHA_RELOAD_DIAGNOSTIC_AUDIT.md уточняет их. Не считать каждую
историческую фразу описанием последнего состояния.

Исходники, конкретный тест и журнал важнее сводного текста. Нашёл противоречие —
укажи его, проверь код и пометь точную границу знания, не исправляй историю молча.

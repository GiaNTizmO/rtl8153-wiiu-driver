# Промпт для первого изучения Claude

Скопировать текст ниже в Claude Code, открытый в E:/PROJECTS/usbethwiiu.

---

Ты подключаешься к существующему проекту драйвера Realtek RTL8153B для Wii U
5.5.6/Aroma. Корень: E:/PROJECTS/usbethwiiu. Нужно изучить текущее состояние и
подготовить техническое ревью для ускорения разработки. Не начинай проект заново.

В этом первом задании только читай и анализируй. Не редактируй исходники, не
запускай сборки/тесты, не обращайся к консоли/FTP/TCP receiver, не отправляй команды,
не устанавливай зависимости. Не изменяй установленные toolchain в UbuntuCafeF.
После изучения я отдельно дам задачу на разработку. При необходимости можешь
сохранить свой отчёт только в docs/handoff/CLAUDE_REVIEW.md.

Прочитай CLAUDE.md и docs/handoff/README.md, затем все документы, перечисленные
там в порядке чтения. После документации проверь соответствующие исходники и
тесты: completion_tokens, firmware_rx/binding, firmware_tx/binding, firmware_io,
UHS transport, native ABI, build scripts и loader contracts/research. Не полагайся
на устаревший корневой README или на наличие готового build ELF. Используй текущий
код как основание, а сохранённые тестовые результаты — только в пределах их покрытия.

Конечная цель: полноценный системный native IOS-NET Ethernet для этого адаптера,
включая штатный DHCP и системный трафик без необходимости Wi-Fi. Рабочий PPC/WUMS
путь с собственным lwIP уже существует; он не является конечным результатом.

Особое внимание:
1. Что доказано на консоли, что только host/ARM-emulation, что не проверено вовсе.
2. Последние firmware_tx_binding.c/h и firmware_io.c/h добавлены перед паузой,
   ещё не собраны и не протестированы. Найди реальные проблемы/недостающие проверки.
3. Сохранность native batch/DMA, pending +/-1, lost-cookie ABI, token lifetime,
   duplicate/stale completion, sync refill и отсутствие обращений после final drain.
4. Главный незакрытый аппаратный барьер — loader/mapping/cache/entry, а не ещё один
   allocation-only тест. Не выдавай симуляцию MMU или allocation result за live loader.
5. Возможности параллельной работы по отдельным файлам без конфликтов с Codex.

Приватные evidence/ содержат firmware и журналы. Не публикуй/не копируй ключи,
OTP/SEEPROM, owner ELF/дампы и полные логи в внешние сервисы или архивы. Если нужный
файл недоступен, явно укажи отсутствие, не выдумывай результат и не подменяй firmware.
Старое разрешение владельца на Mocha allocation diagnostic уже использовано и
не разрешает новый hardware test, USB handoff или установку ops. Текущую готовность
консоли не угадывать. На момент передачи работа Codex поставлена на паузу.

В ответе дай:
- краткое, точное понимание архитектуры и текущей степени готовности;
- таблицу «компонент / доказательство / что осталось»;
- до пяти наиболее существенных замечаний с файлами и номерами строк,
  отдельно факты, вероятные риски и вопросы без доказательств;
- ближайший конкретный блок работ с критериями приёмки и нужными тестами;
- предложение распределения работы Claude/Codex с непересекающимися наборами файлов.

Не обещай дату готовности без оснований, не заявляй успех по числу зелёных тестов.
Не спрашивай заново известные данные — сначала прочитай handoff. После отчёта
дождись моей задачи на разработку.

Драйвер Realtek RTL8153 для CafeOS/Aroma, ориентированный на USB-адаптер
**0BDA:8153** пользователя и Wii U **5.5.6**. Это WUMS-модуль .wms.

**Статус на 09.11.2026: выполнен первый запуск на Wii U. Роутер видит
wiiu-rtl8153, IP 192.168.31.13 и MAC адаптера; с ПК получены 4/4 ответа ping
без потерь, MAC подтверждён через ARP. Базовый обмен через адаптер работает.
Маршрутизация трафика игр и работа Интернета ещё не подтверждены.**

Сборка 0.1.1 исправляет накопление диагностических таймеров при восстановлении
адаптера: в 0.1.0 журнал зафиксировал исчерпание пула lwIP и OSFatal.
Исправление проверено локально на 1000 циклах, но ещё не установлено на Wii U.
Нативная ARM-часть остаётся в разработке; Wi-Fi пока нужен системному стеку.

## Реализация

- Поиск VID:PID 0BDA:8153, выбор интерфейса и bulk endpoints из дескрипторов.
- Чтение внутренней ревизии TCR: RTL8153 5c00/5c10/5c20/5c30 и RTL8153B
  6000/6010. Неизвестная ревизия отклоняется. USB REV_3100 не является TCR.
- Доступ к PLA/USB/OCP с правильными byte enable и little-endian
  преобразованиями на big-endian PowerPC.
- Инициализация из OpenBSD ure(4), заводской MAC, автосогласование
  10/100/1000, USB 2.0 High Speed, RX/TX, приёмные агрегаты и CRC/FCS.
- Три асинхронных буфера UHS RX с доставкой в порядке отправки запросов.
- lwIP IPv4, ARP, DHCP, ICMP, TCP, UDP, DNS и мост Nintendo NSSL через
  localhost, перенесённые из AX88179 Aroma Driver.
- Перехват nsysnet для игр и Wii U Menu через FunctionPatcher.
- Отмена ожиданий при выходе, повторный поиск адаптера, восстановление
  после USB-ошибок, журнал на SD без зависимости от сети.

USB 2.0 совместим с RTL8153. 1000 Мбит/с может быть скоростью линка RJ45,
но не скоростью передачи Wii U: USB 2.0 ограничен 480 Мбит/с до накладных
расходов. Производительность этого порта не измерялась.

## Сборка и тесты

Из PowerShell в папке проекта выполните:

    wsl -d UbuntuCafeF -- bash scripts/test.sh
    wsl -d UbuntuCafeF -- bash scripts/build.sh

Используется существующий /opt/wiiu-rnd/devkitppc-root/rootfs/opt/devkitpro.
Для другого расположения передайте DEVKITPRO через окружение Linux.
Toolchain не устанавливается и не изменяется. Команд make install, pacman,
apt и записи в каталоги toolchain нет. WUMS, libmocha и libfunctionpatcher
собираются в vendor/ проекта. Исходники зависимостей уже включены.

Готовый комплект: dist/sd/. Основной файл:
dist/sd/wiiu/environments/aroma/modules/RTL8153Module.wms.
Отладочные ELF и map находятся в aroma_module/.

## Установка, когда будет доступна консоль

1. Скопируйте содержимое dist/sd/ в корень SD-карты Wii U.
2. Нужны актуальные модули Aroma **FunctionPatcher** и **Mocha**.
   Не запускайте одновременно AX88179Module или другой Ethernet-модуль,
   перехватывающий те же сетевые функции.
3. Подключите адаптер к Wii U, Ethernet-кабель — к роутеру с DHCP.
   На первом тесте сохраните рабочую настройку Wi-Fi: системное состояние
   сети пока зависит от оригинального стека CafeOS.
4. Загрузите Aroma и дождитесь меню. При нормальном ходе драйвер читает MAC,
   поднимает линк и получает отдельный IP. В роутере ожидается MAC
   **00:E0:4C:68:07:2B**; адрес читается из устройства, не зашит в код.
5. Проверьте SD:/wiiu/rtl8153/driver.log, DHCP-таблицу роутера и ping
   адреса адаптера с ПК. Затем проверьте приложение и возврат в меню.

Для удаления удалите RTL8153Module.wms с SD и перезагрузите консоль.
Патч UHS применяется только в RAM, после совпадения VID/PID и поддерживаемого
TCR. Проверяется исходная инструкция по адресу 0x10114338; при несовпадении
запись отклоняется. В NAND драйвер ничего не устанавливает. Проверка
инструкции не заменяет теста на реальном устройстве.

## Настройка

Файл SD:/wiiu/rtl8153/config.ini включён в комплект.
ax — сохранённое имя режима исходного проекта; здесь означает RTL8153/lwIP.
route=native возвращает новые сокеты на оригинальную сеть.
dns=system оставляет системный DNS. nssl=bridge включает мост Nintendo TLS.
pretendo_rewrite=on включает две унаследованные NNCS-подмены для Pretendo;
по умолчанию подмена выключена. FTP/Wiiload handoff — дополнительные
экспериментальные возможности, выключены для первого запуска.
mode=always получает новую аренду DHCP после смены приложения.
Необязательный mode=keep_first повторно использует IP без проверки срока аренды.

## Ограничения

- Это PPC-модуль и совместимый слой, а не новый драйвер внутри IOS-NET.
  В системных настройках он не обязан отображаться как штатный LAN-адаптер.
- Не подтверждены работа без Wi-Fi, Browser, eShop, Download Manager,
  HOME Menu, системные службы и все игры. Покрытие исходного проекта ограничено.
- Нет поддержки vWii и IPv6. Другие VID/PID/TCR, RTL8153D/RTL8156 не включены.
- Не обещается сохранение TCP после отключения кабеля/USB.
- Не проверены реальный DHCP renew/rebind, скорость, совместимость с набором
  модулей владельца и особенности firmware конкретной ревизии RTL8153.

## Исходники и лицензии

Основа Aroma: [wozt/ax88179_aroma_driver](https://github.com/wozt/ax88179_aroma_driver),
commit 558f3a6a4c995590c725dce08eca009e192cff88, GPL-3.0.
Код устройства заменён UHS-портом RTL8153 с BSD-кодом
[OpenBSD ure(4)](https://github.com/openbsd/src/blob/master/sys/dev/usb/if_ure.c).
Уведомления BSD сохранены в driver/rtl8153_bsd.inc и rtl8153_regs.h.
lwIP сохраняет BSD-лицензию; его изменения описаны в vendor/lwip/UPSTREAM.md.
Библиотеки wiiu-env сохраняют собственные лицензии. Версии зависимостей:
docs/dependencies.json. Основной проект GPL-3.0; при распространении бинарника
сохраняйте соответствующие исходники и лицензии.

Проверки и план аппаратного теста: docs/VALIDATION.md.

Исследование подключения к штатному IOS-NET и статус ARM-части:
docs/NATIVE_INTEGRATION.md. Это отдельная незавершённая реализация; текущий
модуль .wms ею не заменяется. Headless Native Probe revision 2 успешно

Прежний сбой Probe был в выводе графики, до чтения памяти IOS-NET.
